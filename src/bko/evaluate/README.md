# `bko.evaluate`: evaluation

Rare-class recall and AUC-PR (scikit-learn), fidelity (SDMetrics), privacy as distance to closest record (SDMetrics), and the validity rate of generated records.

The harness scores every arm (the baselines and the three BKO arms; in the run `g5`, `bko` and the prescribing arm `bko-skeleton`, whose every request carries each record's concepts drawn from the fused BKB (`skeleton`); or, in the free run `g2`, the direct arm `bko-direct`, which draws records from the fused BKB with no API call; ADR [`research/bkb-direct-generation`](../../../docs/adr/research/bkb-direct-generation.md)) on E1's repeated holdouts and judges a candidate arm against E1's criteria. The runs `e3`, `e3-a` and `e3-b` score E1's arms on the Synthea frame instead, each holdout's training rows thinned by the experiment's removal before any arm runs, plus the reference arm `real`, which has no runner and adds back the removed rows (ADR [`research/synthea-downstream-design`](../../../docs/adr/research/synthea-downstream-design.md)). Their held-out ratio reads the split before the removal, and their experiment keeps copies (`Experiment.decontaminate` false): a test record an arm copies is counted and stays in the test split, where E1 removes it. Every holdout writes a `flagged-fingerprint` held-out score of its flagged cells, and `beside.pairable` pairs a holdout only when both files' fingerprints match or either lacks one; such a run writes a `copies-kept` held-out row per holdout, and `pairable`'s `allow_copies`, which `compare` sets for an experiment that keeps copies, lets a holdout with a copy pair when both files hold that row there. The runs `b3-uci` and `b3-synthea` add the CLLM arms `cllm` and `cllm-uncurated` beside `bko`: each of their calls shows training records drawn per cell (module `cllm`), the arm `cllm` drops the rows a boosting classifier fit on the training rows confidently puts at the other label (module `curation`), and every Messages arm refuses data held under an agreement that grants no permission to send it (ADR [`research/cllm-arm-design`](../../../docs/adr/research/cllm-arm-design.md)); `waves` holds the wave helpers every Messages arm's rounds use. `bko.evaluate.experiment.E1` holds the configuration, ADR [`research/e1-evaluation-protocol`](../../../docs/adr/research/e1-evaluation-protocol.md) records the protocol, and [`docs/EVIDENCE.md`](../../../docs/EVIDENCE.md#e1-uci-heart-disease-augmentation) states how each criterion is read. The CLI's `__main__` parses each command, its flags held in `arguments`, and dispatches it; `launch` starts a paid run under `supervise`, which reads each finished segment through `segments`, and a resume's stopped log passes `resumes` before either claims a folder; `context` holds its `Context`, what a command reaches outside the process, `data` holds the `Data` (records, frame, field rows, name, the data use agreement they are held under, and digest) a named run's dataset chooses and every stage of `score` reads, `diabetes` the Diabetes 130 frame, its ICD-9 indicators and its field rows, `scoring` holds the `score` path, `run` scores each holdout's arms, each arm's fill retried and its shortfall kept as a partial fill through `filling` and `shortfall`, and `guided_run` holds `GuidedRun` and `guided_arms`, which build a run's BKO arms over one call log and one candidates file, for the evaluate command and the app alike. The E5 runs keep a share of each cell's training rows before any arm runs (`Experiment.training_fraction`, ADR [`research/e1-evaluation-protocol`](../../../docs/adr/research/e1-evaluation-protocol.md)), and their held-out ratio reads that subsample. `merge` joins holdout slices' scores into one run's, refusing a slice whose sibling `scores.log` names other data, versions or configuration. `shared` rescores a run from its own folder on the test split that neither it nor a compared run copies, writing a `shared-split` row per holdout (module `shared_split`) that `beside` pairs on, after `run_folder` reads each run folder and checks the folders against each other (ADR [`research/shared-test-split-reading`](../../../docs/adr/research/shared-test-split-reading.md)). `rows` rescores a run's folder at its own models through the same checks and a strict check 7, and writes every fill of every arm to a sha-verified `rows.jsonl` that later readings read in place of regenerating, through `read_rows`, `bind` and `frame_of` in `rows_read` (ADR [`research/rebuilt-rows-store`](../../../docs/adr/research/rebuilt-rows-store.md)). `likelihood` reads a run's candidates file, or a sliced run's files as one, and asks whether the BKB likelihood (`bko.gaps.likelihood`) separates the `bko` arm's records by fidelity, G7's free gate (ADR [`research/bkb-candidate-curation`](../../../docs/adr/research/bkb-candidate-curation.md)); `ranking` holds the scorer the gate and the arm `bko-curated` share, which keeps each call cell's highest-scoring rows of twice its quota and marks the rest `dropped-likelihood`. `contradictions` lists, through `bko.gaps.contradictions`, where each mapped frame's training split at holdout seed 0 contradicts its ontology, in the five kinds of ADR [`research/data-contradiction-handling`](../../../docs/adr/research/data-contradiction-handling.md), with no API call. `power.mde` is the smallest mean contrast a design's corrected interval reads above zero at a given power, from the contrast's standard deviation, the holdouts and the held-out ratio. The commands are in [`docs/DEVELOPMENT.md`](../../../docs/DEVELOPMENT.md#evaluation), except `contradictions`, which is under [Gap detection](../../../docs/DEVELOPMENT.md#gap-detection).

- **Dependencies:** The `eval` extra (`pyproject.toml`), `bko.baselines` and `bko.datasets` with their `synth` and `data` extras, and, for the BKO arms, `bko.gaps`, `bko.validate`, `bko.generate` with its `llm` extra and `bko.ontology` with its `ontology` extra; the direct arm reads `bko.generate.direct` in place of the Messages API.
