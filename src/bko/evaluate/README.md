# `bko.evaluate`: evaluation

Rare-class recall and AUC-PR (scikit-learn), fidelity (SDMetrics), privacy as distance to closest record (SDMetrics), and the validity rate of generated records.

The harness scores every arm (the baselines and the three BKO arms; in the run `g5`, `bko` and the prescribing arm `bko-skeleton`, whose every request carries each record's concepts drawn from the fused BKB (`skeleton`); or, in the free run `g2`, the direct arm `bko-direct`, which draws records from the fused BKB with no API call; ADR [`research/bkb-direct-generation`](../../../docs/adr/research/bkb-direct-generation.md)) on E1's repeated holdouts and judges a candidate arm against E1's criteria. The runs `e3`, `e3-a` and `e3-b` score E1's arms on the Synthea frame instead, each holdout's training rows thinned by the experiment's removal before any arm runs, plus the reference arm `real`, which has no runner and adds back the removed rows (ADR [`research/synthea-downstream-design`](../../../docs/adr/research/synthea-downstream-design.md)). Their held-out ratio reads the split before the removal, and their experiment keeps copies (`Experiment.decontaminate` false): a test record an arm copies is counted and stays in the test split, where E1 removes it. Every holdout writes a `flagged-fingerprint` held-out score of its flagged cells, and `beside.pairable` pairs a holdout only when both files' fingerprints match or either lacks one; its `allow_copies`, which `compare` sets for an experiment that keeps copies, lets a holdout with a copy pair. `bko.evaluate.experiment.E1` holds the configuration, ADR [`research/e1-evaluation-protocol`](../../../docs/adr/research/e1-evaluation-protocol.md) records the protocol, and [`docs/EVIDENCE.md`](../../../docs/EVIDENCE.md#e1-uci-heart-disease-augmentation) states how each criterion is read. The CLI's `__main__` parses each command and dispatches it: `context` holds its `Context`, what a command reaches outside the process, `data` holds the `Data` (records, frame, field rows, name and digest) a named run's dataset chooses and every stage of `score` reads, and `scoring` holds the `score` path, and `merge` joins holdout slices' scores into one run's. The commands are in [`docs/DEVELOPMENT.md`](../../../docs/DEVELOPMENT.md#evaluation).

- **Dependencies:** The `eval` extra (`pyproject.toml`), `bko.baselines` and `bko.datasets` with their `synth` and `data` extras, and, for the BKO arms, `bko.gaps`, `bko.validate`, `bko.generate` with its `llm` extra and `bko.ontology` with its `ontology` extra; the direct arm reads `bko.generate.direct` in place of the Messages API.
