# `bko.generate`: record generation

Generate candidate records for each detected gap through the Anthropic Messages API, guided by the relevant ontology relationships, or draw them from the fused BKB with no API call.

`guidance` reads what a request says about each cell at one of six guidance levels, `prompt` renders it, and `calls` asks each cell's quota in chunks through a `Send`, which `api`, the only module that imports `anthropic`, makes real; its `Attempts` middleware counts the HTTP requests behind each call, retries included. `flight` sends a round's independent calls as concurrent waves in plan order through the async client, under the spend ceiling's reservations and the idle limit (ADR [`research/concurrent-call-waves`](../../../docs/adr/research/concurrent-call-waves.md)). `replay` answers a rerun's calls from a call log, and resumes a stopped one: `Replay` is a `Send` that answers each call from a call log in the order the log made them, and `Resume` answers a stopped run's answered calls from its log, then sends the rest live (ADR [`research/call-log-replay`](../../../docs/adr/research/call-log-replay.md)). `decode` turns each reply into candidates, unfiltered and unrepaired, with a placeholder per asked record that did not decode; `spend` prices each call; and `log` writes every request and response with its spend to an append-only JSONL call log; `candidates` writes the candidates file, a header line naming its run, generator and call plan and then one JSON line per asked record, and reads it back for `bko.fusion`. `direct` is the free sampler: it draws each mapped concept present at its share in the fused BKB, seeded, and reads each record's field values from training records that show the drawn concepts (ADR [`research/bkb-direct-generation`](../../../docs/adr/research/bkb-direct-generation.md)). `skeleton` holds a prescribing request's lines: per asked record, the concepts such a draw holds, which `prompt` renders after the level's components. `local` answers the same calls from an on-device model through a llama.cpp server on `127.0.0.1`, and `weights` pins and fetches its GGUF weights (ADR [`research/local-generator-backend`](../../../docs/adr/research/local-generator-backend.md); [`docs/DEVELOPMENT.md`](../../../docs/DEVELOPMENT.md#generation), Local models). ADR [`research/record-generation-design`](../../../docs/adr/research/record-generation-design.md) records the design, [`docs/DEVELOPMENT.md`](../../../docs/DEVELOPMENT.md#generation) holds the command (its definition or `direct` first, its options after), and [`docs/EVIDENCE.md`](../../../docs/EVIDENCE.md#g1-record-generation-through-the-messages-api) (G1) holds its paid runs.

- **Dependencies:** The `llm` extra (`pyproject.toml`), `bko.gaps` with its `data` extra, and `bko.bkb` (`structure`, for the fragments guidance grounds against); the command reads releases through `bko.ontology` with its `ontology` extra.
