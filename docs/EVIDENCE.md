# Evidence register

Sources: [2-pager](../papers/proposal-2-pager.pdf) sections 2, 3 and 5; [Santos et al.](../papers/santos-2024.pdf) section 7 for R1.

The results register: one entry per experiment, reproduction or paid generation run, holding its configuration, its result and what the
result was read against. The criteria live in [RESEARCH.md](RESEARCH.md); an entry links the
section that holds them rather than restating them. An interactive session of
[`bko.app`](../src/bko/app/README.md) is not a run of record: it reads no criterion, and its run
folder is its record.

## How to read an entry

| Field | Meaning |
|---|---|
| Status | `not yet run`, `running` or `complete` |
| Question | What the experiment answers |
| Configuration | Everything needed to rerun it: dataset and split with the dataset snapshot's identity (download date and checksum; for Synthea its `run.json`: jar checksum, seeds, snapshot date, population size and CSV checksums), the generator's model id, sampling parameters and prompt, baselines and controls, metrics and library versions, seeds, the commit, and how the readings [RESEARCH.md](RESEARCH.md#4-success-criteria) leaves open were fixed |
| Runs | One dated row per run: run id, date, commit, where its logs and artifacts live (its run folder under `runs/`, or the `scratchpad/` paths a row names; [DEVELOPMENT.md](DEVELOPMENT.md#runs)), and, for runs that call a paid API, its API spend, the model the API reported, its token counts and where its request/response log lives. A rerun adds a row; a superseded or failed run keeps its row with the reason |
| Result | What was measured, with units, and the command that produced it. Empty until the status is `complete` |
| Read against | The RESEARCH.md section whose criteria judge the result, and the verdict: met, not met, inconclusive (its intervals decide neither way), or a null result reported as such |

Fusion: an arm's rows join the holdout's training rows (`bko.baselines.records.training_set`) before the classifier fits; gap closure after fusion is read by [C1](#c1-gap-closure-after-fusion), not here. An interval criterion is met when every interval it reads lies above its threshold, not met when one lies below it at the family-wise level (each of its k intervals read at confidence 1 - (1 - c)/k, c being `E1`'s confidence), and inconclusive otherwise; a `compare` that refuses the judged run's scores, as it does an empty value a criterion reads, is E1's result.
